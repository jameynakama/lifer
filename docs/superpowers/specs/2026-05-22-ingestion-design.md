# Ingestion Script Design

**Date:** 2026-05-22  
**Scope:** `cmd/ingest` binary -- populates species, recordings, and species_images catalog from eBird, xeno-canto, and Macaulay Library. Group creation is a separate concern.

---

## CLI Interface

```
go run ./cmd/ingest [flags] <region-code> [region-code...]

Flags:
  --max-recordings int   max recordings per species (default 4, ~2 song + 2 call)
  --max-images     int   max images per species (default 3)
  --workers        int   concurrent worker count (default 5)
```

Example for local dev: `go run ./cmd/ingest US-OR`  
Example for Pacific Northwest: `go run ./cmd/ingest US-OR US-WA US-ID`

A `just ingest` recipe wraps this (needs adding to Justfile).

### Environment Variables

| Var | Purpose |
|-----|---------|
| `EBIRD_API_KEY` | eBird + Macaulay Library auth |
| `XENO_CANTO_API_KEY` | xeno-canto auth |
| `ASSETS_DIR` | Local base path for downloaded files (e.g. `./data/assets`) |
| `DATABASE_URL` | PostgreSQL connection string |

## Architecture

```
backend/
  cmd/ingest/
    main.go                       -- entry point, flag parsing, orchestration, worker pool
  internal/
    ebird/
      client.go                   -- eBird API client (species list, taxonomy)
      client_test.go
    xenocanto/
      client.go                   -- xeno-canto API client (recordings by gen/sp + type)
      client_test.go
    macaulay/
      client.go                   -- Macaulay Library client (photos by species code)
      client_test.go
    store/
      queries/ingest.sql          -- new upsert queries
      ingest.sql.go               -- generated by sqlc
```

## Data Flow

### Startup

1. Fetch full eBird taxonomy (`GET /v2/ref/taxonomy/ebird`) → build `map[ebird_code]TaxonomyEntry` in memory (~10k entries, fine)
2. For each region code arg: fetch species codes (`GET /v2/product/spplist/{regionCode}`)
3. Union all species codes, deduplicate

### Per-Species Worker

Runs concurrently up to `--workers` (buffered channel semaphore + `sync.WaitGroup`):

1. Look up `commonName`, `sciName` from taxonomy map; split `sciName` on space → `genus`, `species`
2. Upsert species row (`common_name`, `scientific_name`, `ebird_code`)
3. Query xeno-canto: `gen:{genus}+sp:{species}+type:song` → take top `floor(--max-recordings/2)` by quality A→B
4. Query xeno-canto: `gen:{genus}+sp:{species}+type:call` → take top `floor(--max-recordings/2)` by quality A→B
5. For each recording: download MP3 → `{ASSETS_DIR}/recordings/{ebird_code}/{xeno_canto_id}.mp3`, upsert recording row
6. Query Macaulay: `GET /v2/ref/media/best?species={ebirdCode}&mediaType=photo` → take top `--max-images`
7. For each image: download JPG → `{ASSETS_DIR}/images/{ebird_code}/{macaulay_id}.jpg`, upsert species_image row

**Error handling:** log and continue per species. One bad API response does not abort the run. Final summary line: `"ingested N/M species"`.

**Progress:** `log.Printf` lines per species -- `"ingesting Spotted Towhee (US-WA)..."`, `"done 42/150"`. No progress bars.

### Worker Pool

Buffered channel as semaphore + `sync.WaitGroup`. `errgroup` is not used here because it cancels the whole group on first error -- we want per-species fault tolerance instead.

## Schema Changes

New migration:

```sql
ALTER TABLE recordings ADD COLUMN type TEXT NOT NULL DEFAULT '';
```

The `Recording` model gains `Type string` after `just generate`.

---

## sqlc Queries (`internal/store/queries/ingest.sql`)

Three new queries, all idempotent -- safe to re-run:

- **UpsertSpecies** -- `ON CONFLICT (ebird_code) DO UPDATE` common_name, scientific_name
- **UpsertRecording** -- `ON CONFLICT (xeno_canto_id) DO UPDATE` file_path, quality, type
- **UpsertSpeciesImage** -- `ON CONFLICT (macaulay_id) DO UPDATE` file_path, credit

---

## File Storage

Files land at:
- `{ASSETS_DIR}/recordings/{ebird_code}/{xeno_canto_id}.mp3`
- `{ASSETS_DIR}/images/{ebird_code}/{macaulay_id}.jpg`

In dev: Go serves `ASSETS_DIR` via `http.FileServer` mounted at `/assets`.  
In production: nginx serves the same directory at the `/assets` path prefix; Go never touches file-serving.  
Future: swap `ASSETS_DIR` for S3/R2 by changing download target and `ASSETS_BASE_URL` -- DB paths stay the same.

---

## Testing

Each client (`ebird`, `xenocanto`, `macaulay`) gets a `_test.go` using `httptest.NewServer` with canned JSON fixtures, asserting correct struct output. No DB required for client tests. `cmd/ingest/main.go` is thin orchestration and does not need its own tests.
